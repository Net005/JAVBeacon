Start source scraping

New releases only - fastest catch-up option: skips the detail page entirely for any release already on file for this site, so nothing already saved is ever re-fetched or updated. Best after enabling a site for the first time or after downtime, when many pages back are already known. Quick refresh - the same add-only behaviour (nothing already saved is updated), but every scanned page is fully re-fetched rather than skipped, so it also catches a release changing status (e.g. an announced release gaining its release date) sooner. This is what the scheduled Quick refresh job runs. Full refresh - adds new releases and updates every existing release the scan finds with the freshly scraped details.

SCRAPING

Quick refresh (scheduled scan)

The main scheduled scan. Each run scans this many pages of every enabled site and only adds releases it hasn't seen before - it never re-scrapes or updates a release already in the database. Use Full refresh below for a separate schedule that also updates existing releases.

SCRAPING

Cloudflare protection (FlareSolverr)

Some sites serve a Cloudflare challenge page instead of the real content. When a FlareSolverr URL is configured, every scrape (scheduled or manual) routes through it instead of attempting a direct request, so Cloudflare-protected pages still load. Leave the URL blank to scrape directly.

SCRAPING

Full refresh (scheduled scan)

A second, independently-scheduled scan that scans this many pages of every enabled site and both adds new releases and updates every existing release found on those pages, refreshing its metadata from the live site. This does more work per release than Quick refresh, so it's disabled by default and typically runs less often - enable it once you're ready for a heavier scheduled scan.
